- 2026-10-25 — Pilot 1 runtime findings (V11a): a team ran one API + two worker processes on one SQLite file on 0.2.1 and needed nine app-local workarounds; the framework now covers them, generically. (1) sqlite: busy timeout (`busyTimeoutMs`, 5000), WAL + `synchronous=NORMAL` for file databases, `BEGIN IMMEDIATE` for every transaction, migrations re-check `murmur_migrations` inside their transaction; because a second process got `database is locked` at once (no busy handler) and a deferred read-then-write transaction cannot be retried by SQLite. (2) `murmur start` registers the loader in-process (`import(registerUrl)` → `module.registerHooks`) instead of re-execing; because supervisors (systemd, docker, k8s) signal the pid they started and a launcher in front of the runtime broke stop/restart; `module.register()` itself is deprecated in Node 26 (DEP0205), so the task's "module.register" became registerHooks. `murmur test` keeps children (node:test isolates files; `--json --coverage` needs `--enable-source-maps` at startup, verified `setSourceMapsEnabled` does not remap) but forwards SIGINT/SIGTERM and exits with their code; `dev` keeps its restartable child. (3) An ingress capability starts only when a selected piece serves through it (or needs it) and its reserved config `enabled` is not false, logging `<name> not started: <reason>`; because worker processes started with `--only` opened the API port too and collided. (4) `GET /healthz` is a default: a piece serving it wins; because apps need a real readiness check (db, queue) on the conventional path. (5) `req.peer` (socket) and `req.ip` (first X-Forwarded-For only with `trustProxy: true`); because rate limits and audit logs need the caller and trusting the header by default is spoofable. (6) `defineApp`/`createRuntime`/bus take `DeliveryPolicyInput` (every retry field optional, jitter 0.5 default; app and runtime retries merge); because `Partial<DeliveryPolicy>` was shallow and the documented shape did not compile. (7) `runInContext(run, fn)` in `@murmur/node/testing`; because capability tests had to fake ALS by importing private `runContext`. (8) The router's 404/405 envelope comes from the token's `errors` setting, not the first route; because a token with no route answered the default envelope. Also `--only pieces/<id>` accepted like every other command. docs/cli.md, docs/ingress.md, docs/capability-authoring.md, spec.md

## 2026-10-25 — Research closed: stop investing

Three uncounted pilots on the same spec, kickoff and Sonnet team: NestJS, murmur 0.2.1, murmur 0.3.0. Hidden suite 686 / 687 / 684 of 692 (a tie; the same three traps missed by every arm). Cost $41 / $72 / $64, agents 31 / 84 / 50, source 8.9k / 12.0k / 11.7k LOC. murmur won on merge conflicts (7 conflicted merges vs 1–2) and dependency count (513 vs 139); v0.3 cut edge code from 58.6 to 16.1 LOC per route. It lost on performance: about 3× NestJS CPU per request, a 4 % idle tick, 1.5–2.6× API memory, and the 0.3.0 team built a write-per-request rate limiter on the durable-storage path that collapsed list and search under load. The framework is frozen at 0.3.0 with its known issues; no v0.4. The lab (spec, hidden suite, traps, harness, container perf) is published alongside as the reusable part. Full account: `docs/research/post-mortem.md`.
